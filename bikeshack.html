Performance

Bike Shack


Status: Completed — speed and Core Web Vitals overhaul
Walkthrough video coming soon Check back shortly for a video tour of this project.

This project was a performance overhaul of the Bike Shack storefront, driven by Lighthouse scores and real-world load times rather than guesswork.

Store speed isn't a vanity metric. Every extra second before a page becomes usable costs conversions, and slow pages get pushed down in search results. The problem is that most stores get slow gradually — an app here, a tracking script there, a few oversized hero images — so there's rarely one thing to fix.

The work broke down into three areas: cutting the JavaScript payload by removing scripts the store no longer used and deferring the ones that didn't need to run immediately, optimizing the image pipeline so the browser downloads correctly sized and modern-format images instead of full-resolution originals, and rebuilding the critical path so the content a visitor sees first loads before anything below the fold competes for bandwidth.

The result is a storefront that feels immediate on mobile, where most of the traffic comes from, and a set of habits the store can keep following as new content gets added.
